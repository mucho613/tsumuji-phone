# 手動受入試験

- Tailscale 上の Asterisk に、ユーザ ID を SIP 識別子（AoR）と
  ダイジェスト認証名の両方に使って登録・登録解除
- Asterisk 再起動、Tailscale 再接続、アプリ再起動後の再登録
- ユーザ ID 1～32 文字とパスワード 1～128 文字について、許可する記号、
  最小値、最大値、範囲外の境界値を検証
- 先頭の 0 を含む内線番号へ発信できることを検証
- 内線と外線について発信／着信を各 20 回反復
- 30 分間の連続通話で音声、RTP、メモリ利用が安定
- 発信取消、着信拒否が正しく終了し、拒否は 486 になる
- 110、118、119 が SIP INVITE の送信前に拒否される
- DTMF が RTP telephone-event とインバンドの両方で動作
- ミュート中も呼が維持され、解除後に送話が復帰
- ウィンドウを閉じても待受し、トレイから復帰／終了できる
- マイク、通話出力、着信音出力を別々に選択できる
- Windows／Ubuntuで「この端末のIPアドレス」欄が表示されず、一意に検出した
  Tailscale IPv4へSIP/RTPをbindする
- Tailscale IPv4が0件または複数件の場合は接続を開始せず、理由を表示する
- 待受開始後は接続設定に差分がない限り「変更を適用」を表示しない。SIPサーバー、
  ユーザID、新しいパスワードの変更時だけ表示し、値を戻すと非表示になる
- ネットワーク切断、スリープ復帰、Tailscale 再接続、Asterisk 再起動後に回復
- 保存済み資格情報や完全な電話番号がログへ出ない

## Android

- Android 12/API 31 以上の `arm64-v8a` 実機と `x86_64` エミュレーターへ APK を
  インストールして起動できる
- SIP サーバーとユーザ ID は再起動後も設定画面へ復元され、保存済みパスワードは
  Android Keystore で保護されて UI やログへ露出しない
- 待受開始後にアプリを完全終了して起動すると、停止／開始操作なしで「接続中」から
  「待受中」へ移行し、そのまま発信できる
- 初回登録の明示的な成功／失敗が直ちに表示され、応答がない場合は 10 秒で
  「接続失敗」となり、自動再試行しない
- 接続失敗の理由と「再接続」が電話画面に表示され、保存済み設定で直ちに再試行できる
- 登録中も番号を入力できるが発信は無効で、登録完了後も入力済み番号へ自動発信しない
- 登録完了後に Tailscale または SIP サーバーとの接続を失うと、5 秒間隔、
  最大 60 秒で自動復旧する。復旧しなければ接続失敗へ移行する
- 自動復旧中に通話が継続している場合、その通話を切断しない
- 設定差分がある場合だけ「変更を適用」が表示され、新しい設定へ登録し直せる。
  通話中は変更適用、待受停止、再接続が無効になる
- 明示的な待受停止後の次回起動では自動接続せず、保存済み設定は再利用できる
- Tailscale 未接続やマイク権限なしを登録前に検出し、解決に必要な理由を表示する
- FCM payload に wake/cancel と一時 call token 以外の着信情報を含めない

### Android Push 対応後

- Google Play Services 利用不可や通知権限なしを待受開始前に検出し、解決方法を
  表示する
- 一度限りの pairing code で端末を登録し、同じ code を再利用できない
- device credential が Android Keystore で保護され、UI、ログ、FCM payload に
  露出しない
- アプリを閉じた状態と画面ロック状態から wake push を受信し、30 秒以内に
  OpenSIPS へ登録して着信 UI を表示する
- INVITE 受信後に内線の発信者番号を表示し、外線で番号が通知されない場合も
  着信へ応答できる
- 発信側が呼を取り消したとき、cancel push により着信 UI と一時登録が終了する
- 応答、拒否、切断、ミュート、受話口／スピーカー／Bluetooth 切り替えが
  Core-Telecom と実際の音声経路へ反映される
- 端末側 48 kHz と PCMU/RTP 8 kHz の間で、内線／外線とも双方向音声が安定する
- 端末再起動後、最初のロック解除を経て push 待受可能状態へ復帰する
- 明示的な待受停止後は push 着信しないが、再開時に保存済み資格情報を再利用できる
- バッテリー最適化の除外なしで、SIP や foreground service を常駐させずに
  一晩の待受と翌日の着信が成立する
- 一つの SIP ユーザ ID に二台目を pairing した場合、同時に有効な Android 端末が
  一台だけになる

実機試験中も既存電話機を利用可能な状態に保ちます。
