# 手動受入試験

- Tailscale 上の Asterisk に、ユーザ ID を SIP 識別子（AoR）と
  ダイジェスト認証名の両方に使って登録・登録解除
- Asterisk 再起動、Tailscale 再接続、アプリ再起動後の再登録
- ユーザ ID 1～32 文字とパスワード 1～128 文字について、許可する記号、
  最小値、最大値、範囲外の境界値を検証
- 先頭の 0 を含む内線番号へ発信できることを検証
- 内線と外線について発信／着信を各 20 回反復
- 30 分間の連続通話で音声、RTP、メモリ利用が安定
- 発信取消、着信拒否が正しく終了し、拒否は 486 になる
- 110、118、119 が SIP INVITE の送信前に拒否される
- DTMF が RTP telephone-event（RFC 4733）で動作
- ミュート中も呼が維持され、解除後に送話が復帰
- 発信・着信とも通話成立前は経過時間を表示せず、成立時に `00:00` から開始する。
  バックグラウンドから戻ってもリセットせず、1時間未満は `MM:SS`、1時間以上は
  `H:MM:SS` で表示し、通話終了時に消える
- ウィンドウを閉じても待受し、トレイから復帰／終了できる
- 通常モードでウィンドウを最小化またはトレイへ格納して着信させると、
  ウィンドウが一度表示され、着信音が鳴り、応答／拒否できる。ウィンドウは
  最前面固定されず、発信側取消後も自動で隠れない
- 着信を通知しないモードでは、着信時に画面表示、タスクバーの注意要求、着信音が
  発生しない。手動でアプリを開くとその着信へ応答／拒否できる
- 通知モードを設定画面とトレイの双方から切り替え、表示が同期し、アプリ再起動後も
  維持される。着信中の切替では通常→通知しないで直ちに消音し、逆方向では
  画面表示と先頭からの着信音再生が始まる
- 着信相手がSIP URIでもユーザ部分だけを表示し、空またはanonymousは
  `番号非通知` と表示する
- デスクトップの着信音出力をOS既定または列挙された機器から選択でき、選択欄を
  開くたびに一覧を再取得する。選択機器を外した状態、再生中に外した状態の双方で
  OS既定へフォールバックし、理由を表示する
- WAV、MP3、OGG Vorbis、FLACを着信音として取り込み、元ファイルを移動／削除しても
  再生できる。不正ファイルでは現在の選択を維持し、既定へ戻せる
- 音量0、50、100を試し、試聴中の変更が直ちに反映される。試聴は10秒、画面遷移、
  実着信、停止操作で終了する
- 応答、拒否、発信側取消、待受停止、通常→通知しない切替、アプリ終了の各操作で、
  着信音と注意要求が500ms以内に停止する
- 選択音と既定音の再生失敗時にもSIP着信へ応答／拒否でき、同じ呼で無限再試行しない
- Windows／Ubuntuで「この端末のIPアドレス」欄が表示されず、一意に検出した
  Tailscale IPv4へSIP/RTPをbindする
- Tailscale IPv4が0件または複数件の場合は接続を開始せず、理由を表示する
- 待受開始後は接続設定に差分がない限り「変更を適用」を表示しない。SIPサーバー、
  ユーザID、新しいパスワードの変更時だけ表示し、値を戻すと非表示になる
- ネットワーク切断、スリープ復帰、Tailscale 再接続、Asterisk 再起動後に回復
- 保存済み資格情報や完全な電話番号がログへ出ない

## Android

- Android 12/API 31 以上の `arm64-v8a` 実機と `x86_64` エミュレーターへ APK を
  インストールして起動できる
- SIP サーバーとユーザ ID は再起動後も設定画面へ復元され、保存済みパスワードは
  Android Keystore で保護されて UI やログへ露出しない
- 待受開始後にアプリを完全終了して起動すると、停止／開始操作なしで「接続中」から
  「待受中」へ移行し、そのまま発信できる
- 初回登録の明示的な成功／失敗が直ちに表示され、応答がない場合は 10 秒で
  「接続失敗」となり、自動再試行しない
- 接続失敗の理由と「再接続」が電話画面に表示され、保存済み設定で直ちに再試行できる
- 登録中も番号を入力できるが発信は無効で、登録完了後も入力済み番号へ自動発信しない
- 登録完了後に Tailscale または SIP サーバーとの接続を失うと、5 秒間隔、
  最大 60 秒で自動復旧する。復旧しなければ接続失敗へ移行する
- 自動復旧中に通話が継続している場合、その通話を切断しない
- 設定差分がある場合だけ「変更を適用」が表示され、新しい設定へ登録し直せる。
  通話中は変更適用、待受停止、再接続が無効になる
- 明示的な待受停止後の次回起動では自動接続せず、保存済み設定は再利用できる
- Tailscale 未接続やマイク権限なしを登録前に検出し、解決に必要な理由を表示する
- Android を再起動してロック解除した後、Tsumuji Phone を開かなくても「常時接続
  VPN」の Tailscale が自動復帰し、tailnet 内の SIP サーバーへ到達できる
- 同じ SIP ユーザ ID を別の SIP クライアントへ登録せず、OpenSIPS に対象端末の
  Tsumuji Phone Contact だけが存在する
- FCM payload に `type=wake` と一時 call token 以外の情報を含めない
- 通話画面にラベル付きのミュート、現在音声経路、切断ボタンが表示され、外線 `117`
  の `dialing`／`connecting` 中から受話口とスピーカーを切り替えられる
- Bluetooth 通話機器と USB-C 有線ヘッドセットが利用可能経路として現れ、選択時に
  入出力が機器へ移る。通話中の切断では呼を維持して別経路へ退避し、再接続後に
  再選択できる
- 通話中にアプリをバックグラウンドへ移して戻した場合、実際の現在経路と候補を
  表示し、通話終了時に経路状態と選択パネルが消える
- 「付近のデバイス」権限は最初に音声経路一覧を開いたときだけ要求され、拒否しても
  Bluetooth 以外の通話を継続できる。Android 設定で許可すると Bluetooth が現れる
- 経路準備または切り替えが5秒で完了しない場合は自動再試行せず、現在経路を維持して
  理由を表示する。Bluetooth 機器名を保存、ログ、Push payload へ出さない
- `117` または内線との通話中に最近使ったアプリの一覧から Tsumuji Phone を閉じると、
  相手側も5秒以内に終話し、サーバーの手動操作なしでアプリをすぐ開き直して同じ
  宛先へ再発信できる

### Android Push 待受

- Firebase 構成ファイルがなければ Android build が配置方法を示して早期失敗する
- 通知権限は設定画面のボタンを押したときだけ要求され、拒否しても通常のSIP発着信を
  使用できる。拒否後は Android の通知設定を開ける
- 10分の pairing code は一度だけ使え、再使用と期限切れを拒否する
- ペアリング後に gateway URL とランダム端末 ID が復元され、端末資格情報は
  Android Keystore で保護される
- FID は Android Keystore で暗号化され、Rust、Web UI、SIP Contact、
  クリップボード、ログに値が出ない
- REGISTER の Contact に FID でなくランダム端末 ID の `pn-prid` が含まれる
- Push gateway の内部 wake API は loopback だけで到達でき、端末向け API は
  Tailscale Serve の HTTPS 経由で到達できる
- gateway は FID、端末資格情報、call token、payload をログへ出さない
- data-only、高優先度、TTL 30秒、collapseなしで、`type=wake` と256 bitの
  Base64URL `callToken` だけを送る
- アプリのタスクを閉じた状態、`adb shell am kill` 後、画面ロック＋Dozeから wake
  を受信して Activity を開かずに foreground service を開始する
- 端末再起動後、Tsumuji Phone を一度も開いていない状態から Push 着信、応答、
  双方向音声、切断が正常に完了する
- gateway の wake API 要求から15秒以内、FCM受信から10秒以内にAsteriskへSIP登録する
- 「着信接続中」通知は無音・低優先度で、着信がなければFCM受信から30秒以内に
  SIP登録、foreground service、通知が終了する
- 保留された INVITE に対して端末が再登録すると着信音付き CallStyle 通知が表示され、
  通知の応答・拒否で SIP と Core Telecom の状態が一致する
- 通知から応答した後に Activity を前面へ出さなくても双方向音声が流れ、通話は
  30秒を超えて維持され、CallStyle 通知の「通話終了」で
  SIP、Core Telecom、通知がすべて終了する
- Android 14 以上で全画面着信が未許可なら設定導線が表示され、許可後は画面ロック中
  の着信で応答・拒否を直接操作できる。未許可時またはサイレントモード等による
  全画面抑制時は従来の CallStyle 通知を維持する
- 全画面着信から応答した通話の終了後、Activity が表示中なら通常の待受へ自動的に
  戻り、そのまま発信できる
- 通話終了直後の再着信でも毎回 Push と再登録が行われ、同じ内線へ再接続できる
- アプリからの発信も Core Telecom と CallStyle 通知へ登録され、通知の
  「通話終了」で切断できる
- 登録失敗／10秒無応答時は再試行せず、「着信接続に失敗しました」通知を残し、
  次回起動時に識別子を含まない詳細理由と所要時間を表示する
- 同じ call token の再送を2分間無視し、生値を保存・記録しない
- 待受停止中、登録済み、登録中、通知権限なし、未知の type の wake は既存のSIP
  状態を変えず安全に無視する
- Androidの「強制停止」は受入試験に含めない

実機試験中も既存電話機を利用可能な状態に保ちます。
